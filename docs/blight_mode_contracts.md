# Контракты режимов Скверны (A — поставляется, B — проект)

Документ фиксирует информационный контракт текущего варианта A и проектного
варианта B. Тесты на реконструкцию текущего выравнивания уже реализованы;
вариант B настоящей скрытой роли пока не реализован.

## Контекст: атака доказана

Тест `test_attack_reconstructs_hidden_alignment_from_public_observations`
восстанавливает выравнивание всех игроков из данных, доступных обычному
клиенту: публичный журнал (последние 20 записей, копимые клиентом), маркеры
хода («🎲 X: …», «⏭️ Ход переходит к X»), публичное поле `current_player`.
Анонимизация имени в записи журнала утечку не закрывает: партия строго
пошаговая, «кто-то осквернил» между маркерами однозначно приписывается
игроку на ходу. Тест `test_suspicion_evidence_is_publicly_reconstructible_in_variant_A`
дополнительно доказывает, что внутренние улики ботов (`blight_stage_sources`)
точнозаново восстанавливаются из публичных данных — привилегии у ботов в
варианте A нет (в удобстве — есть: человеку надо считать самому).

Следствие: текущий `cult_visibility=hidden` — это **не** тайная роль, а
**дедукция по публичным действиям**. Это выбор дизайна, а не баг.

## Вариант A — «Динамическая фракция, публично вычислимая» (поставляется)

- Контракт: выравнивание = детерминированная сумма публичных действий
  (corrupt +1 / purify −1, порог ±2, гистерезис). Любой игрок МОЖЕТ
  восстановить любое выравнивание; интерфейс может не показывать его
  (интерфейсное удобство), но секретом это не является.
- Что гарантируется: корректность арифметики, гистерезис (одиночное действие
  не меняет фракцию), скрытие ЧИСЛОВЫХ деталей (score/слёзы) в UI до порога.
- Что НЕ гарантируется: конфиденциальность принадлежности к фракции.
- Требование изоляции: НЕ ПРИМЕНЯЕТСЯ. Вместо него — спецификация
  вычислимости: атакующий тест обязан ПРОХОДИТЬ (реконструкция совпадает с
  реальностью). Он и есть контракт.
- Игровой смысл: «игра в открытую в масках» — дедукция тривиальна для
  внимательного игрока; ценность несут побочные механики (слёзы, благословение,
  обличение как ставкапри уликах).

## Вариант B — «Действительно скрытая роль» (проект, не реализован)

- Контракт: принадлежность к Культу/Ордену — скрытое состояние, НЕ
  восстанавливаемое из публичных данных однозначно.
- Проверяемое требование информационной изоляции: атакующий тест (наблюдатель
  с полным публичным журналом, историей ходов, публичной картой и любым
  детерминированным алгоритмом) НЕ способен восстановить принадлежность лучше
  базовой ставки априорного распределения ролей. Формально: P(угадал|атака)
  ≤ P(угадал|априори) + ε, ε задаётся (например 0.05) на всём множестве
  наблюдаемых траекторий. Тест обязан падать при любой утечке.
- Минимальные механики, удовлетворяющие контракту (на выбор дизайна, здесь
  только наброски):
  1. Скрытый выбор роли в начале партии (одноразовый, не через публичные
     действия); заражение/очищение доступно всем независимо от роли;
     роль даёт пассивные перки и скрытые цели.
  2. Разделение «действие» и «мотив»: одинаковые действия доступны обеим
     сторонам, а роль влияет на скрытую победу (условия, счётчик).
  3. Случайный компонент зашифрованного состояния (обязательство/раскрытие),
     если роль назначается скрыто — чтобы владелец мог доказать раскрытие.
- Ключевое следствие: раз действия одинаковы для всех ролей, журнал больше
  не вычисляет роль; улики становятся вероятностными (паттерны трат, выбор
  целей), что и есть детектив.
- Экономика/победа требуют собственного синтетического тестирования —
  текущие A/B-прогоны к варианту B неприменимы.

## Рекомендация

Вариант A остаётся текущей базой для игры и синтетики. Первый человеческий
плейтест следует проводить в `mode=factions`, `cult_visibility=open`: игроки
должны видеть сторону напрямую, без ложного обещания секретности. Значение
`cult_visibility=hidden` в варианте A — это эксперимент «дедукция по публичным
dействиям», а не настоящая тайная роль; в интерфейсе оно должно называться
именно так.

Если цель — настоящий тайный Культ, вариант B проектируется отдельным циклом
(дизайн → контракт → тест изоляции → экономика). Результаты баланса варианта A
на B автоматически не переносятся.
