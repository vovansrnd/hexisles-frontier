# Методика плейтеста «Культ ↔ Орден» и сбор логов

## 1. Запуск (ничего менять не нужно)
Лобби по умолчанию уже стоит на проверяемой конфигурации: Скверна «Культ ↔ Орден», сторона «Открытая», 12 очков, туман войны, быстрый старт выкл., интенсивность 40%, маршруты выкл., мягкий разбойник, сложность «Скайнет». Достаточно ввести имя и нажать «Начать игру» (с ботами) или переключиться на «С друзьями» и отправить ссылку из комнаты ожидания.
Сервер: `./run_local_v5.sh`. Архив включён по умолчанию (`HEXISLES_MATCH_ARCHIVE=1`, файл `data/hexisles.sqlite3`). Признак успеха: после конца партии в консоли сервера строка `[archive] saved match ...`.

## 2. Проведение
Первые 5–10 завершённых партий, правила не менять между ними. Не подсказывать. После партии три вопроса из `docs/blight_live_playtest.md` (понятность, выбор, информация) и запись `match_id` + ответов в таблицу: match_id | игрок | оценка 1–5 | где запутался | менял ли сторону и почему.

## 3. Что присылать на анализ
1. `python3 tools/analyze_blight_archive.py --limit 20 --json summary.json` (сводка без сырых состояний).
2. Таблицу ответов игроков.
3. Только по моему запросу: `python3 match_archive_cli.py export <ID> -o private-match-export.json` (содержит имена и скрытое состояние, не публиковать).

## 4. Что будет посчитано
Действия мода на игрока (заражения, очистки, обличения), смены стороны, ОП из мода и доля обеих дорожек, длина партии, сравнение с ботовой базой (медиана 96 ходов, ~2,2 ОП мода на игрока), совпадение ответов с поведением.
Критерии решения — в протоколе координатора: не менять сразу несколько параметров; сначала интерфейс и объяснения, затем одна проверяемая гипотеза правила.

## 5. Wagtail: логи в PostgreSQL
- В версии для Wagtail журналирование уже есть (`PendingGame*` во время партии, `CompletedGameMatch.package` по окончании; временные строки удаляются, завершённые архивы хранятся). Профиль «Компактный» подходит для плейтестов; «Подробный» включать только точечно.
- Раздувание базы: хранить `package` сжатым (zlib/gzip, JSON сжимается ~8×), строки `CompletedGamePlayer` (сводки) хранить всегда, а `package` старше N дней или сверх последних M партий обнулять командой `game_archive prune --days 60 --keep-last 200`. Первые 5 партий измерьте (`game_archive stats`) и умножьте на ожидаемое число партий.
- Не писать в БД на каждый ход бота: накапливать события в памяти партии и сбрасывать пачкой в конце хода игрока и при завершении.

## 6. Нагрузка на хостинге
Снимок состояния ранней партии: ~19 КБ, ~2,2 КБ после gzip (карта около 16 КБ почти не меняется). Рекомендации: включить gzip; отдавать геометрию карты один раз; ответ «без изменений» по `state_version`; опрос раз в 3 с вне своего хода (1 с в свой) и пауза при скрытой вкладке; не отправлять `legal_actions` вне своего хода; боты ходят пачкой за один запрос, а клиент проигрывает цепочку событий анимацией.
